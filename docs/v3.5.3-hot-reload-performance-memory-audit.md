# v3.5.3 hot-reload, performance, and memory audit

## Scope

This pass audited Better Inventory's Ctrl+Shift+R lifecycle and the long-lived state used by inventory, Character Overview, Armoury, GlobalStore, Sire Melk, Hadron, search, sorting, discard automation, Curio acquisition, Auto Crafter, item customization, markers, and optional-mod integrations.

The goal is bounded ownership: after DMF unloads the mod, no live view or global bridge should retain callbacks or cache roots from the previous Better Inventory module generation. Normal view behavior, sorting order, text-search semantics, and automation limits remain unchanged.

## Confirmed lifecycle gap

DMF invokes each mod's `on_unload` before removing hooks and rebuilding mod code during Ctrl+Shift+R. Better Inventory previously implemented `on_disabled` but not `on_unload`, so its normal teardown did not run on a full mod reload.

The most important retained roots were live inventory/store panel callbacks. Those closures capture the old Better Inventory module graph. Search input ownership and view fields also needed explicit release for views that survive a reload.

A second card-generation pass found two less obvious roots. `ViewElementGrid` copies blueprint visibility/change callbacks into every generated widget and retains the configured blueprint table itself. Character Overview separately publishes Better Inventory blueprints into Darktide's shared `InventoryViewContentBlueprints` table. Both could keep the previous module generation reachable when the surrounding view survived Ctrl+Shift+R.

## Implemented fixes

- Added an explicit reload teardown that shuts down Auto Crafter, discard/Curio automation, persistence, diagnostics, marker registries, Character Overview state, view sessions, search runtimes, and transient layout caches.
- Added a generation-owned view lifecycle. Better Inventory removes its panel callbacks and elements before unload, then adopts each surviving inventory or vendor view once after the new generation loads.
- Added generation ownership for every Better Inventory-managed equipment grid. Deferred native presentation callbacks are cancelled at unload, retained card entry IDs are invalidated, and each surviving Inventory, Hadron, Armoury, Brunt, GlobalStore, or Melk grid performs one native lifecycle rebuild with the newly loaded blueprint callbacks. A populated, untagged grid from a pre-v3.5.3 release is treated as a legacy generation and adopted once too.
- Retired Character Overview's four globally published custom blueprint types to minimal native update/destroy placeholders at unload and when first upgrading from an untagged older release. A surviving individual-layout view then uses Darktide's complete layout switch once to destroy native icon resources and recreate its cards from the new generation. A failed transitional rebuild remains retryable instead of being falsely marked current.
- Preserved ordinary `_setup_sort_options` behavior. Native view rebuilds still fully rebuild Better Inventory sort options; only the per-frame repair path is generation-gated.
- Added an all-view Equipment Text Search release path so focused input, controller ownership, remembered per-view UI state, and Melk routing cannot retain the old generation.
- Added a reload-specific item-customization shutdown. It closes the editor, drains deleted records, flushes pending persistence, clears the change listener, and releases cached records without performing the normal disable-time Name It ownership handoff or re-enabling hooks.
- Kept DMF's `on_disabled(initial_call)` argument separate from reload state. A truthy first-initialization flag can no longer select the reload-only teardown path; only `on_unload(exit_game)` does so.
- Made the Auto Crafter HUD bridge identity-owned and removed it only when it still belongs to the unloading Better Inventory generation.
- Changed Automatic Curio Buyer unload cancellation to destroy and drop its read-promise container instead of allocating a replacement container that the unloading module can never use.

## CPU and allocation findings

The audit retained the existing search architecture and removed two avoidable presentation allocations:

- Equipment Text Search already coalesces rapid edits into one settled query, warms a bounded 16-item slice, reuses view-owned projection buffers, and performs no work after release.
- Search ranking reorders existing layout entries in double buffers; it does not recreate equipment cards or invoke GodRolls/ItemSorting comparators for every keystroke.
- Darktide ignores replacement blueprint tables when all incoming entry IDs still resolve to the live widget generation. Better Inventory now detects that exact native reuse case before deep-cloning/configuring the full card blueprint, so settled search, sort, and same-generation reorder presentations reuse the existing cards and renderer resources. Generation changes deliberately invalidate IDs and cannot enter this fast path.
- The compact Curio detail-header blueprint is now cached by its source blueprint and height setting on the owning stats grid. Repeated presentations reuse the adjusted header, setting changes replace it once, and view teardown explicitly drops the cache.
- Sort priority caches are view-owned and released with their sessions.
- Character Overview and marker registries use weak ownership plus explicit close/destroy/disable fallbacks.
- Auto Crafter, Games Lantern queues/imports, discard transactions, equipment persistence, and GlobalStore portrait generations already expose bounded shutdown/retirement paths.
- Shared `ViewElementGrid` update/draw chains remain unhooked, avoiding a permanent per-frame charge on unrelated Darktide or third-party grids.

Full card allocation remains necessary when a category changes membership, a store tab supplies new offers, a grid is first opened, or a module generation changes. Native widget destruction remains responsible for renderer/icon resources; GlobalStore additionally retires its asynchronous portrait generation before destructive card replacement.

Broad cache removal, manual `collectgarbage()` calls, or rebuilding cards after every query would increase CPU/stutter risk and can fight Stingray's own collection cadence. The audit therefore releases Better Inventory-owned roots deterministically and leaves collection timing to the engine.

The standalone performance harness measured the settled search UI gate at 0.35 microseconds per frame over 100,000 frames with approximately 0.062 KiB transient allocation. A 128-card settled query averaged 0.23 ms; committing an already-ranked 130-card grid averaged 131 microseconds while preserving entry identity. These synthetic figures are regression indicators, not promises for every game/mod configuration.

## Assurance boundary

Lua memory is not expected to return to the exact pre-reload number immediately. Ctrl+Shift+R necessarily parses every enabled mod again, creates replacement closures/tables, and depends on Lua garbage collection plus the engine allocator's high-water behavior. Better Inventory cannot force other mods, Darktide, or the allocator to return reserved pages to the operating system.

The v3.5.3 guarantee is narrower and testable: Better Inventory now releases the references it owns, so repeated reloads should no longer produce monotonic growth caused by its old live-view callbacks, live card blueprint generations, Character Overview's shared blueprint registrations, deferred grid presentations, search state, customization/cache state, global HUD bridge, or an abandoned Curio promise container.

## Live validation protocol

1. Record Lua memory and Better Inventory CPU after entering the Mourningstar and waiting for a stable baseline.
2. Open inventory, Character Overview, Armoury/GlobalStore, Melk, and Hadron at least once. Run 20 varied searches and change several sort modes.
3. Close the views, wait for the memory graph to settle, then perform ten Ctrl+Shift+R reloads at a steady cadence.
4. Reopen the same views after each reload and verify panels, sorting, search focus, card interaction, and automation controls.
5. Distinguish a retained-root leak (monotonic post-settle growth every cycle) from allocator high-water memory (growth that plateaus and remains reusable).

Automated coverage exercises reload teardown, idempotent repeated release, deferred-presentation cancellation, exact-once surviving-grid and Character Overview adoption, reorder-only blueprint reuse, compact Curio-header cache replacement/release, callback removal, search release, customization cache release, and the normal sort-option rebuild path. In-game soak testing remains necessary because the test harness cannot observe Stingray's allocator or third-party mod roots.
