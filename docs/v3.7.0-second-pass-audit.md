# v3.7.0 adversarial branch audit — 2026-09-09

**Update:** Both findings below are remediated in the v3.7.1 working tree, with regression checks. The measurements and verdict below describe the original c2cd679 audit, not the remediation. See `v3.7.1-curio-consecration.md`.

**Verdict: useful architecture and efficiency improvements, but not ready for regression-free sign-off. Two additional regressions reproduced.**

Scope: all 43 changed files across the eight commits from `991312c` (main / v3.6.0 baseline) through `c2cd679` (v3.7.0 HEAD). Reviewed runtime changes, affected callers, test and coverage changes, generated manifests, localization and release documentation. This is an audit, not a remediation or live-game acceptance pass. Runtime files were not modified.

## Confirmed findings

### P1 — The new percentage pattern introduces quadratic parser CPU

Location: `scripts/mods/BetterInventory/auto_crafter/games_lantern/parser.lua:113`.

The replacement pattern contains `width:%s*([^%%"]+)%%`. Both `%s*` and the following capture can consume whitespace. When the closing percent sign is missing, Lua retries the capture for each possible whitespace split, rescanning the suffix. The new forward-only card delimiter scanner does not bound this work inside a card.

Reproduction: take the repository's valid HTML fixture and replace its first `style="width:80%`-shaped prefix with `style="width:` followed by N spaces and `x`, leaving the closing quote and the rest of the page intact. Every tested input remains below the 2 MiB limit. LuaJIT 2.1 measurements, median of three runs:

| Spaces | Baseline 991312c | v3.7.0 working tree |
| ---: | ---: | ---: |
| 1,000 | 0.227 ms | 4.525 ms |
| 4,000 | 0.435 ms | 67.574 ms |
| 16,000 | 0.911 ms | 1,082.439 ms |

Four times the input produces roughly sixteen times the new parse time. Import parsing runs synchronously from `ImportController:update`; the read deadline cannot interrupt the parser. A malformed page can therefore stall the game thread despite the advertised parser bound. No large or live payload was dispatched to the game.

Fix direction: extract a bounded width attribute once, then trim and validate its numeric contents. Avoid overlapping unbounded repetitions. Extend the parser work-budget regression to malformed inner attributes, not just missing card delimiters. The existing parser also skips the malformed stat; that acceptance behavior predates this branch and is not counted as a separate new regression here.

### P2 — Invalid stat rejection can be converted into legacy mark fallback

Locations: `auto_crafter/games_lantern/resolver.lua:455`, its consumer at `:1016`, and `auto_crafter/games_lantern/queue.lua:347` (all under `scripts/mods/BetterInventory`).

The new duplicate-normalized-label check returns `custom_stat_ambiguous` immediately. The existing unknown-mark compatibility path treats that reason as permission to choose fallback stats, instead of a terminal malformed-input rejection. The early return also bypasses later profile validation.

Reproduction uses the existing unknown-cleaver-mark fixture. Give the first two source stats the distinct strings `Future Stat A` and `Future Stat A!` (identical after resolver normalization), with values totaling 379. These strings are not duplicates under the parser's lowercase-only comparison.

- Baseline resolver rejects with `custom_stats_invalid_total`.
- v3.7.0 resolver accepts the identity with `custom_stats_enabled=false`, a chosen dump stat, and `mark_fallback.adjustments.stats=custom_stat_ambiguous`.
- `stat_fallback` is nil, so the newly introduced fallback-stat queue guard and confirmation label do not apply.

This violates the branch's promise that malformed/duplicate identities remain rejected and incompatible targets require the new explicit stat review. **The normal aggregate crafting confirmation is still required; this is not evidence of an unattended purchase or a bypass of all confirmation.** Legacy mark-fallback notifications still apply.

Fix direction: distinguish terminal malformed-input errors from recoverable catalogue/schema mismatches. Validate the whole source profile before compatibility fallback, and ensure all applicable replacement-stat paths carry the intended review metadata. Test the cross-product of unknown marks, normalized duplicate labels and incompatible totals, not only each condition separately.

## Verification and positive assessment

- Complete behavior suite: **57 files / 198 named cases passed**, zero failed or unrun cases.
- Recursive coverage: **90 modules**, no policy failures; reported aggregate line coverage **70.95%**.
- Architecture, schema drift, runtime bundle and Lua AST structure checks passed. Bundle: 92 files, metadata 3.7.0. Branch whitespace check passed.
- New read-only diagnostic `tools/audit_v370_second_pass.py` reproduces both findings against the pinned baseline and current source. Run `python tools/audit_v370_second_pass.py`. Its assertions characterize the current defect and must change when fixes land; its timing output is diagnostic, not a portable CI threshold.
- Reviewed local native Promise behavior, native widget pass ordering, DMF persistence/hook interfaces, and installed WKC provider/generation behavior. These local sources support integration reasoning; they do not substitute for running the game.

| Area | Assessment |
| --- | --- |
| Architecture | Existing core/host separation remains intact. Reusing the canonical operation arbiter removes duplicate safety logic. No new dependency or speculative abstraction was added. |
| Reload ownership | Tiny persistent generation/count fence and scoped backends are a sensible separation from retired UI/controller graphs. Current tests pass for old dispatch rejection, cross-generation settlement and disable/re-enable scope invalidation. No additional regression confirmed here. |
| Cleanup | Independent protected cleanup calls reduce failure propagation; facade multi-return repairs preserve useful operation diagnostics. No additional regression confirmed in the changed boundaries. |
| Import liveness | 30-second read deadlines, 250 ms store polling, meaningful store readiness and per-request callback identities improve bounded work and recovery. Parser finding above prevents a blanket bounded-import claim. |

Provider-keyed weak geometry caching respects layout generation and provider replacement. The 120-draw counter regression passes (one geometry read, 120 kill lookups). |
| Queue polling | Narrow `stop_requested()` query removes full queue/job copies from that polling path while preserving detailed snapshots for actual consumers. This is a targeted allocation improvement. |
| Stat compatibility | Deterministic native-order replacement and mandatory review are sound for the covered uniquely mapped case. Error classification leaks across the legacy fallback boundary, as reproduced above. |
| Tests | Recursive module identities and explicit coverage policies improve accountability. Passing named branch contracts still do not prove combinations not exercised by their fixtures. |

The facade reports only **5.35% line coverage** and passes through its declared branch-contract policy. This is disclosed by the existing audit and is not a newly introduced defect. Several boundary tests execute extracted snippets or replace upvalues rather than the entire bootstrap lifecycle. The two passing-but-reproducibly-broken cases above demonstrate why the green suite is supporting evidence, not a no-regression certificate.

## Remaining acceptance

Fix both findings before sign-off, then run focused counterexamples and the existing suite/gates. Keep tests for valid imports, source-stat preservation, fallback confirmation, timeout/cancel/retry, old callbacks, repeated reload, optional WKC absence/replacement and live layout changes.

No live game rendering, account writes, multiplayer interaction, FPS/frame-time profiling or native process execution acceptance was performed. The WKC and queue improvements have source/harness support; **whole-game performance improvement and absence of live regressions remain unproven**. There is no evidence from this pass that a larger project restructure is needed: the required fixes belong at the existing parser and resolver boundaries.
