# v3.2.5 GlobalStore tab-lifecycle audit

## Reported symptom

Repeatedly alternating GlobalStore's melee, ranged, and Curio categories—each containing roughly 100–150 offers—raised Lua memory and left Better Inventory near 0.160 ms/frame instead of its normal settled 0.04–0.06 ms range.

## Source-level cause

GlobalStore adds a character portrait to each offer card through `Managers.ui:load_profile_portrait`. Its loaded and unloaded callbacks close over the card widget, and the returned load ID is stored only in `widget.content.portrait_load_id`.

Darktide's `ViewElementGrid:_on_present_grid_layout_changed` destroys the entire current widget generation when an incoming category contains an entry without a live `entry_id`. GlobalStore previously unloaded portrait IDs only when `CreditsVendorView.destroy` ran. A category switch therefore destroyed the widgets carrying those IDs before GlobalStore could retire the portrait requests. The UI manager's pending callbacks retained the otherwise-dead widgets and their attached card data.

Better Inventory had two secondary amplification paths:

- its weak favorite-marker set could still see a retired widget while GlobalStore's portrait callback strongly retained it;
- inactive Equipment Text Search restarted its 16-item projection warm cursor at item one on every presentation of the same authoritative offer table.

## v3.2.5 mitigation

Immediately before a destructive GlobalStore main-grid presentation, Better Inventory now:

1. detects the same rebuild boundary used by Darktide's grid;
2. unloads every outgoing `portrait_load_id` and clears ownership before calling the UI manager, restoring the ID only if that call fails;
3. starts a fresh weak marker generation so reconciliation never scans retired cards;
4. leaves same-generation/in-place search sorting and all auxiliary grids untouched.

The unload adapter is allocated once when the runtime is installed. The path runs only on a GlobalStore main-grid presentation, adds no frame/update hook, and owns no growing registry.

Search warming now binds its cursor to the authoritative source layout. Repeated captures of that same table continue the existing pass; a completed source is not warmed again, and replacement sources or view release discard the old reference.

## Verification

The deterministic stress harness alternates 40 disjoint generations of 150 cards. It proves:

- 6,000 outgoing portrait loads are retired;
- retained portrait resources never exceed the current 150-card generation;
- marker tracking is empty at each generation boundary;
- an unchanged layout triggers no unload or marker reset;
- an unavailable portrait service fails safely and preserves the load ID for GlobalStore's normal destroy fallback;
- 50 repeated captures of one search source do not reset the warm cursor, and a completed cache does no further projection work.

The full behavior suite remains the regression gate. Live performance should be evaluated after the final category finishes loading; short-lived portrait/card construction cost during an actual tab transition is expected, while continuing growth or a permanently elevated settled baseline is not.
