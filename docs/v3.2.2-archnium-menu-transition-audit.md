# v3.2.2 Archnium menu-transition compatibility audit

Date: 2026-08-27

## Scope and evidence limit

Archnium reported crashes while swapping loadouts and changing cosmetics or gear in the mission-ready screen on Better Inventory v3.1.0. No console log, crash locals, or installed-mod list was available during this audit. The archives in `Archinium_investigation` are candidate conflicts selected for research; they are not evidence that Archnium installed any of them.

Therefore v3.2.2 must not claim a confirmed root-cause fix. It adds two narrow lifecycle/ownership mitigations found through source comparison and leaves unrelated third-party behavior untouched.

## Confirmed local mission-ready crash found during v3.2.2 validation

A local reproduction after this audit produced GUID `760c40a8-fc4f-4656-8b44-77d64178dbea` while transitioning from the Mourningstar into an Auric mission-ready lobby. Unlike Archnium's still-unlogged v3.1.0 report, this complete log proves a separate v3.2.x regression introduced with Equipment Text Search:

- `LobbyView.update` called `_initialize_background_world`;
- `ScriptWorld.spawn_level` failed with `Level not loaded` for `content/levels/ui/lobby/lobby`;
- `LobbyView.init` had correctly selected that level and passed its dynamic level-package descriptor to `BaseView.init`;
- Better Inventory's global `BaseView.init` search-decoration hook declared only the arguments through `context` and invoked the original without trailing arguments;
- the dropped first trailing argument was `dynamic_package_name`, so Darktide never acquired the lobby level package before entering the view.

The hook exists only to decorate `CraftingMechanicusBarterItemsView` definitions. It now preserves all trailing native arguments for every view while retaining that one supported decoration. Regression coverage passes both a decorated Hadron view and an unrelated `LobbyView` through the hook and proves the dynamic package plus an additional future argument retain identity and order.

This local failure is highly actionable but cannot retrospectively prove Archnium's v3.1.0 cause: Equipment Text Search and this hook did not exist in v3.1.0. It does prove why current v3.2.2 validation crashed at the same transition category.

## FirstFleet is a separate proven failure

FirstFleet's supplied full log identified:

- `InventoryWeaponsView` / inventory renderer failure;
- style `better_inventory_equipped_highlight`;
- missing `content/ui/materials/frames/line_thin_dashed_animated`;
- renderer value `128` as material flags, not a material path.

That failure was fixed in v2.9.8 by replacing the crafting-package-only material with inventory-owned `frame_tile_2px` and repairing stale Better Inventory highlight widgets. Current Darktide source still loads the replacement material in inventory UI. Archnium's report names broader loadout/cosmetic/mission-ready transitions and supplies no matching renderer error, so treating both reports as identical would be unsupported.

## Darktide lifecycle findings

Current source establishes these ownership boundaries:

- `InventoryView` owns Character Overview loadout widgets. `_switch_active_layout` destroys and recreates native layout widgets.
- `InventoryBackgroundView` owns profile-preset changes and backend equipment promises.
- `LobbyView` observes loadout changes and refreshes mission-ready weapons, talents, and cosmetics.
- `MissionIntroView` is a separate view lifecycle.
- `UIManager.is_view_closing(view_name)` and `UIManager.view_instance(view_name)` expose authoritative close/replacement state.
- `ViewElementGrid` is shared across equipment, vendors, cosmetics, profile presets, and third-party panels; a global hook is not proof of Better Inventory ownership.

## Finding 1: shared-grid hooks acted before rejecting unsupported grids

Before v3.2.2, Better Inventory's global `ViewElementGrid.present_grid_layout` hook eventually failed open for unsupported layouts, but only after some Better Inventory work had already run:

- marker invalidation;
- blueprint inspection or cloning;
- synthetic on-present callback wrapping;
- optional layout preparation.

The active inventory view could also lend its configuration to a nested grid from the same call stack. Global widget creation and window-size hooks likewise inspected shared grids before establishing ownership. Candidate profile-preset/cosmetic mods use these exact shared seams.

### Fix

`scoped_grid_view` now resolves only:

- the exact active view's `_item_grid`; or
- a parent whose class is explicitly supported by Better Inventory search/layout integration.

Unsupported profile-preset, cosmetic, lobby-preview, and unknown grids return directly to the prior/native hook before mutation. Widget marker/material attachment and post-window clipping use the same ownership guard.

This is compatibility containment, not a mod-specific override. Hook order remains composable.

## Finding 2: delayed Character Overview work could outlive active generation

Better Inventory registers Character Overview views in a weak table and performs bounded delayed Curio/icon reconciliation. Native `on_exit` and `destroy` hooks unregister normal closures. During complex chained menu transitions, however, another mod can extend the hook chain while Darktide has marked the view closing or installed a replacement generation before final teardown reaches Better Inventory.

Calling native `_switch_active_layout` on that retired generation is unsafe because it destroys/recreates UI widgets while other transition owners may be tearing them down.

### Fix

Before any delayed work, `character_overview_view_retired` now rejects:

- malformed or destroyed views;
- views reported closing by `Managers.ui:is_view_closing`;
- old generations when `Managers.ui:view_instance(view_name)` returns another non-nil instance.

A nil manager or nil current instance fails open. Nil is valid during activation, and optional API errors are contained with `pcall`. Retired views are unregistered and their Better Inventory references are released.

## Reviewed non-findings

- Equipment persistence already binds work to account, character, view generation, and close/reset lifecycle. No broad change was justified.
- Better Inventory does not hook `LobbyView` or `MissionIntroView`; adding such hooks without a crash trace would increase collision risk.
- Global renderer interception is not justified. FirstFleet's material was identified and repaired at Better Inventory-owned widget seams.
- No candidate-specific disable list was added. Presence of a candidate archive is not proof of a defect.
- No third-party data structures, preset caps, cosmetic templates, lobby spawn slots, or input hooks are rewritten.

## Regression coverage

Automated coverage now proves:

- supported inventory grids still receive Better Inventory marker/material behavior;
- profile-preset grids receive no Better Inventory widget marker state;
- unsupported grid presentation gets its original callback arguments unchanged;
- destroyed and closing Character Overview views retire;
- replaced view generations retire;
- same-generation and transient nil-instance activation remain active;
- UI-manager contract failures fail open;
- static ownership checks prevent global shared-grid update/draw expansion.

## Remaining validation

Archnium's newest complete `console-*.log` and mod list remain required to identify the actual crash. Useful evidence must include the first script error and stack/locals before secondary teardown errors. Until then, v3.2.2 should be described as removing two credible Better Inventory crash vectors, not confirming Archnium's report fixed.
