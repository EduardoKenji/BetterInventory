# BetterInventory v2.3.0 memory and performance audit

Status: completed on 2026-08-13 on branch `perf/2.3.0-memory-cpu-audit`.

Branch base: `56a58e3259e0aac437da7c89859b2b2a38813155` (`main`). Runtime/archive verification head: `69216d2`. This document records every branch commit through that head; the documentation commit containing this record is intentionally not self-referential.

## Outcome

The audit found and remediated all identified actionable lifetime and frame-cost gaps. The runtime now has explicit ownership for module state, optional-mod wrappers, active views, child processes, temporary transport files, and presentation caches. Repeated UI work is cached, gated by active views, fast-pathed on stable frames, or polled at bounded intervals.

No remaining unbounded collection, orphaned callback, retained view, accumulating UI layer, timer-per-card, or repeated process/file lifetime was found by the static audit and automated suite. This is not a claim that an engine-hosted Lua mod can be proven leak-free without runtime observation: release validation should still include repeated open/close, hot-reload, optional-mod enable/disable, and multi-run soak tests in Darktide.

## Runtime validation still recommended

Before release, exercise these engine-dependent paths because static tests cannot model renderer and third-party-mod behavior completely:

1. Repeatedly open/close melee, ranged, and Curio inventories; toggle only **Show inventory options widget** and verify clean hide/restore behavior.
2. Confirm an old profile containing `enable_inventory_options_panel_prototype = false` still receives the scalable panel.
3. Run Ctrl+Shift+R, reopen Mod Options and inventories, and confirm no duplicate wrappers, widgets, or dependency state.
4. Soak pulsing highlights with inventories closed/open and repeat Character Overview transitions.
5. Enable/disable Lantern and run repeated Games Lantern import/cancel/clear operations on Windows; exercise Wine/Proton separately when available.
