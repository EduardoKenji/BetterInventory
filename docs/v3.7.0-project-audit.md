## Findings and acceptance criteria

### A01: Reload ownership boundary

`BetterInventory_auto_crafter.shutdown` drops its controller while an old native
request may remain unsettled; `DiscardTransaction.new` constructs an independent
arbiter. A harness blocked an external dispatch before shutdown and allowed it
after shutdown with the old operation still pending. No duplicate real write was
issued. Keep a minimal process-lifetime write fence, not an old UI/controller
graph. Only matching settlement/reconciliation may clear it; never a timeout.
Test pending write -> new module generation -> reject new write -> settle -> recover.

### A02: Parser complexity

Repeated card opening delimiters without a closing marker cause repeated suffix
scans before the card budget counts anything. About 87 KB / 3,000 openers took
785 ms locally, below the 2 MiB ceiling. Use a forward-only delimiter scan and
test incomplete/nested delimiters and bounded work, without a parser dependency.

### A03: Lua multiple returns

`local ok, snapshot = controller and pcall(...)` collapses returns through `and`:
the public snapshot always falls back to unavailable. Mutation diagnostics and
interruption decisions lose flags. Queue clearing similarly loses its reason.
Use explicit branching and test actual facade functions, not replacement stubs.

### A04: Catalogue read liveness

`resolving_catalogues` has no effective deadline; a never-settling promise keeps
clear busy after 10,000 updates. The host must update this stage too. Add a bounded
read deadline, generation invalidation, retry, and late-callback tests. Read
timeouts must not release destructive-operation quarantine.

### A05: Native store coherence and waiting work

An empty layout table is currently considered ready even with zero visible
offers. Conversely, waiting rebuilds context each update (10,001 scans over
10,000 updates). Require meaningful matching offers; poll at a bounded cadence
with a retryable deadline. Test nil -> empty -> populated, mismatch and late reads.

### A06: Challenge classification

A valid fixture plus `<!-- recaptcha helper -->` or a login-to-comment footer is
rejected as a challenge. Classify challenge-only pages without discarding valid
structured builds. Retain rejection of actual challenge and incomplete content.

### A07: Cleanup fault isolation

An exception in one shutdown step skips later lifecycle release. DMF catches the
outer callback but cannot resume skipped steps. Protect independent cleanup,
log failures, continue, and test injected failures and repeated teardown. Do not
clear unsettled account ownership merely because cleanup failed.

### A08: Coverage enforcement boundary

Top-level globbing excludes 26 nested modules from the coverage gate, although
they have behavioral tests. Discover recursively with relative-path identities,
set honest baselines, and exercise facade and cross-generation wiring. Coverage
percentages alone do not demonstrate transition safety.

### A09: WKC repeat work

Each stable visible card performs five geometry reads and three kill lookups per
draw: 600 / 360 over 120 draws. WKC already caches template data, so this is modest
redundancy, not a demonstrated leak. Share per-draw results and respect existing
layout generation, settings changes, live kills, and mod reload/absence.

### A10: Queue snapshot allocation

Stop/quarantine polling deep-copies jobs/catalogues/results to read one flag.
A synthetic two-job, 120-snapshot probe allocated ~4.1 MiB with GC paused. This is
temporary churn, not retained memory. Add a narrow state query and preserve full
snapshots only for consumers that need them.

### A11: Compatible stat fallback with review

Five-stat targets outside 60..80 / total 380 fail even when the weapon and traits
are identified. This is intentional validation, not a bug to silently remove.
Recognize well-formed non-target distributions, retain identified weapon/traits,
and require explicit review of a deterministic native-compatible target before
crafting. Negative/non-finite/out-of-range/duplicate/ambiguous values stay rejected.
Test both supported fallback and fail-closed boundaries; update user-facing text
including Chinese when new localization keys are introduced.

### A12: Duplicate safety implementation

`BetterInventory_discard_transaction.lua` embeds ~131 lines of fallback arbiter
already implemented by `BetterInventory_operation_arbiter.lua`. Runtime supplies
the canonical implementation. Require that implementation and use it in tests;
fail the capability clearly if unavailable. Avoid broad module reshuffling.

### Safety batch evidence

- DMF persistent table holds only write count/generation; native promise settlement
  survives controller retirement. Backend scopes reject late dispatch/retries from
  retired generations, including disable/re-enable without a module reload.
- Guard remains active during disable while writes settle. DMF removes all hooks
  synchronously during reload; the next loaded guard reads the same fence. This
  does not claim protection from other mods bypassing native service methods or
  issuing writes during framework initialization before this mod loads.
- Targeted guard, backend, facade, feature/arbiter and reload tests passed; AST and
  architecture gates passed. Fault injection confirms unrelated teardown continues.

### Import recovery batch evidence

- Forward-only bounded card extraction rejects 30,000 incomplete delimiters
  promptly; valid fixture plus login/captcha footer remains accepted.
- Read stages have a 30-second deadline and 250 ms store polling. The host ticks
  catalogue resolution too; explicit clear cancels reads and makes late callbacks
  inert. Each catalogue attempt has a distinct token, including store-change
  retries inside the same import generation.
- Tests cover 12,000 waiting updates with at most 49 context scans, empty/stale/live
  native layouts, never-settling catalogues, cancellation, retry and stale results.
- User weapon-choice deliberation does not consume the next read deadline.

### Efficiency batch evidence

- A native logic pass resolves WKC values before both render passes. A 120-draw
  regression now performs 120 kill lookups and one geometry read (previously
  360 / 600). Layout-generation changes and live kills refresh correctly.
  Geometry caching is weak-keyed by WKC's geometry provider and disabled without
  its generation API, so replacing the provider also invalidates cached settings.
- Stop polling uses `Queue:stop_requested()`, leaving deep snapshots for callers
  that require job details. No retained per-frame item cache or update hook added.

### Coverage enforcement batch evidence

- All 90 runtime modules are now discovered recursively using relative paths.
  Duplicate basenames cannot share credit; foreign sources are excluded; new
  unassigned modules fail. The reporting regression constructs these cases.
- All 26 nested modules have explicit line gates, with no zero-percent exemptions.
  Existing overlay tests now report their real source identity; new clipboard and
  HUD behavioral tests cover the other formerly uncredited adapters.
- 57 test files and the expanded coverage gate pass. Thresholds preserve measured
  baselines rather than claiming exhaustive coverage: OS shell adapters remain at
  15% line floors with command-construction contracts, panel blueprints at 25%.
  Native Windows/Wine process behavior and live rendering still need acceptance.
- The facade retains its branch-contract policy plus actual snapshot regressions;
  the new branch matrix explicitly covers facade teardown, reload fence and read
  deadlines. A low facade line percentage is not represented as full integration
  coverage.

### Stat compatibility batch evidence

- Uniquely mapped five-stat profiles with valid integer values in 0..100 but an
  incompatible target distribution receive a deterministic 60/80/80/80/80 target
  in native stat order, choosing the lowest source stat as the dump stat. Ties
  use native order. Original values remain available in the external model.
- Source traits remain unchanged and must still resolve through native catalogues.
  Ambiguous/duplicate mappings, non-finite/negative/out-of-range/fractional values
  remain rejected. Unknown stat identities do not gain this new fallback.
- Staging emits a mandatory notification, labels the queue stats for review and
  changes the second-click confirmation label. Queue.start itself rejects these
  jobs without explicit confirmation; the host still validates cost signatures.
  English and Simplified Chinese strings are included.
- Regression cases cover below-target/all-zero/all-80 distributions, malformed
  values, duplicate labels, trait preservation, no dispatch before review, and
  the actual panel confirmation label.
