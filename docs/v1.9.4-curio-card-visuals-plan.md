# BetterInventory v1.9.4 Curio card visuals plan

Status: alignment correction implemented on this branch; pending in-game visual validation
Branch: `feature/1.9.4-curio-overlay-decoration-alignment`
Baseline: BetterInventory `1.9.3` on `main`  
Target version: `1.9.4`  
Prepared: 2026-08-07

## Outcome

Version 1.9.4 should make the existing **Show rarity colour strip** option work consistently for Curios and add an optional Darktide-native visual treatment to populated detailed Curio cards in Character Overview.

The native-look option should retain BetterInventory's useful title, four stat lines, and item-level text. It should change only the card's visual shell: use Darktide's ornate Curio inner frame and native Curio portrait geometry. It must not replace the detailed card with Darktide's information-poor native blueprint.

The current overlay alignment uses an 8 px downward adjustment for the title and all four stat rows, gives the centered title a 19 px horizontal inset with a 1 px left bias without changing its two-line height, moves the item level 16 px left and 16 px higher, moves equipped/favorite markers 10 px left, and anchors the favorite/checkmark marker 40 px below the complete title band so it aligns with the primary toughness row after its runtime positioning callback. These adjustments are scoped to the native-overlay branch so the disabled appearance and ordinary inventory/vendor cards remain unchanged.

## Viability decision

Both changes are viable without new assets, asynchronous work, backend calls, or persistent state.

- The Curio colour strip already exists in BetterInventory's cloned detailed item pass template. It appears uncoloured because Darktide's native `gadget_item_slot` lifecycle colours `background_gradient` but, unlike the weapon lifecycle, does not colour `rarity_tag`.
- Darktide's native Curio card already exposes the desired `inner_frame` pass using `content/ui/materials/frames/line_thin_detailed_03`, as well as native Curio icon geometry. BetterInventory can clone those definitions into its hybrid detailed Curio blueprint.
- The work is UI-local and event-driven. No polling, timers, coroutines, purchase coordination, or saved rotation state are involved.

## Current architecture and root cause

### Character Overview Curios

`character_overview_curio_blueprint()` in `BetterInventory.lua` deliberately builds a hybrid card:

1. Clone the detailed generic Character Overview item blueprint and its rich pass template.
2. Adopt the native Curio slot size, currently `193 x 250`.
3. Use Darktide's native `InventoryViewContentBlueprints.gadget_item_slot` init, update, and destroy callbacks so item icons retain the native managed-resource lifecycle.
4. Run the result through `Layout.configure_native_item_blueprint()`.
5. Reposition BetterInventory title, Curio stats, icon, and item-level passes.

This preserves icon ownership correctly, but it combines passes and lifecycle callbacks that were not originally paired.

### Why the Curio colour strip is blank

The generic detailed item pass template contains `rarity_tag`, and `BetterInventory_layout.lua` correctly sizes it and applies the `show_rarity_tag` visibility setting.

Darktide's generic/weapon item callbacks assign the rarity colour to both `background_gradient.color` and `rarity_tag.color`. The native Curio `gadget_item_slot` callback assigns only `background_gradient.color`. Consequently, the cloned strip is visible but keeps its default uncoloured style.

This is a colour synchronization defect, not evidence that the Curio blueprint needs a second strip pass.

### Why the ornate overlay is absent

Darktide's `ItemPassTemplates.gadget_item_slot` includes a Curio-specific `inner_frame` pass with the ornate corner-line material. BetterInventory starts from the generic detailed item pass template, which has ordinary frame/corner passes but not the Curio-specific `inner_frame`.

The native Curio icon is also laid out as a centered `256 x 128` landscape portrait near the top of the `193 x 250` card. BetterInventory currently enlarges and repositions the generic icon for its own detailed layout. The new option must switch these visual definitions without removing detailed text passes.

### Coordinate contract and regression guard

Darktide's `UIWidget` pass renderer uses this order:

1. Resolve the pass alignment against its parent size.
2. Add `style.offset[1]` to the final X position.
3. Add `style.offset[2]` to the final Y position.
4. Add `style.offset[3]` to the render-layer Z position.

The axes are not inverted: index 1 is X, index 2 is Y, and index 3 is Z. The important distinction is that `offset[1]` and `offset[2]` are additive deltas after alignment; they are not always the left/top edge of the pass.

For the native Curio title, `horizontal_alignment = "center"` already computes the centered pass position. With a `193 px` card and a `155 px` title band, the renderer first computes `(193 - 155) / 2 = 19 px`. Therefore:

- The `19 px` inset belongs only in `size[1] = card_width - 2 * inset`.
- `offset[1] = -1` moves the already-centered title one pixel left.
- Using `offset[1] = inset - 1` incorrectly applies an additional `18 px` rightward shift. This was the cause of the title moving farther right in the previous build.

For top-aligned markers, positive Y moves down. The compact yellow circled checkmark is BetterInventory's `favorite_icon` marker; it is distinct from Darktide's native `equipped_icon` texture. MyFavorites and the Equipped Icon+ synchronization callback can rewrite the favorite marker's Y every update, so the native overlay must apply its extra X shift and a minimum Y equal to the title bottom plus a 40 px gap after those callbacks. The runtime hotspot must receive the same final coordinates. The item level is bottom-aligned, but the same screen-space rule still applies: positive `offset[2]` moves it down, so its native-overlay Y delta must be negative when moving it higher.

Future native-overlay changes must document every coordinate as `x = offset[1]`, `y = offset[2]`, and `z = offset[3]`, identify the pass alignment, and explain whether a value is an absolute alignment result or an additive delta. Never put a centered pass's horizontal inset into `offset[1]`.

## Implementation plan

### 1. Add the setting and localization

Files:

- `scripts/mods/BetterInventory/BetterInventory_data.lua`
- `scripts/mods/BetterInventory/BetterInventory_localization.lua`
- `scripts/mods/BetterInventory/BetterInventory.lua`
- `tests/test_settings.py`

Actions:

1. Add `character_overview_use_native_curio_overlay` as a checkbox with `default_value = false`.
2. Add English name and tooltip strings and the repository's Chinese fallback entries in the same style as adjacent Character Overview settings.
3. Register the setting in `option_dependency_entries`.
4. In `refresh_option_dependencies()`, enable it only when `enable_character_overview_curio_details ~= false`.
5. Include it in the setting-change branch that refreshes affected views/layouts.
6. Extend tests for group order, default value, localization completeness, and dependency enable/disable behavior.

Do not add a profile migration. A new default-off boolean naturally preserves current behavior.

### 2. Synchronize rarity-strip colour at the shared layout boundary

Primary file: `scripts/mods/BetterInventory/BetterInventory_layout.lua`.

Implement a small bounded helper near `apply_item_customization_style()`:

1. Resolve the item through the existing `item_from_element()` helper.
2. If `widget.style.rarity_tag` and an item exist, obtain `Items.rarity_color(item)`.
3. Copy or clone that colour into `widget.style.rarity_tag.color` only during card init/data refresh.
4. Run per-item custom background colour application afterward, so a user's custom card colour remains the final authority.
5. Leave visibility exclusively under `show_rarity_tag`; colour synchronization must not force the pass visible.

Call the helper from the configured card init and `update_data` wrappers immediately before `apply_item_customization_style()`. This placement is preferred over a Character Overview-only patch because:

- it repairs any other hybrid/native Curio surface that has the same lifecycle mismatch;
- generic weapon and Curio cards remain idempotent;
- custom item background colours continue to override base rarity colour;
- equipped-item changes that invoke `update_data` are retinted without reopening the view.

Do not mutate the strip every frame. The base colour changes only when the widget receives a new item/data payload.

### 3. Compose the optional native Curio visual shell

Primary file: `scripts/mods/BetterInventory/BetterInventory.lua`.

Inside `character_overview_curio_blueprint()`:

1. Read `character_overview_use_native_curio_overlay` once while constructing the cloned blueprint.
2. When disabled, preserve the current pass set and geometry exactly.
3. When enabled, find the native `inner_frame` pass in `ItemPassTemplates.gadget_item_slot`, clone it, and append it only when the detailed pass template does not already contain `style_id = "inner_frame"`.
4. Never share or mutate the global native pass table. All inserted passes and mutable nested style tables must be deep clones.
5. Apply Darktide's native Curio icon dimensions/alignment/offset from the native pass instead of duplicating magic numbers where practical. If the runtime source does not expose a usable style table, use the verified native fallback geometry (`256 x 128`, top-centred, native vertical offset) in one named local helper.
6. Keep the current BetterInventory display-name, four Curio-stat, and item-level passes.
7. Resolve z-order explicitly. The inner frame must render above the background/icon but below all readable BetterInventory text. Raise only affected text pass offsets if their current z value is not already above the native frame.
8. Keep pointer/hotspot behavior, equipped indication, favorite marker, and managed icon lifecycle unchanged.

Prefer helper functions such as:

- `pass_by_style_id(pass_template, style_id)` if an equivalent is not already available locally;
- `clone_native_curio_inner_frame(pass_template)`;
- `apply_character_overview_curio_icon_geometry(icon_pass, native_overlay_enabled)`.

Helpers should be pure blueprint construction operations. They must not retain widget, renderer, item, or view references.

### 4. Preserve text readability within native geometry

The native frame and portrait occupy more of the upper card than BetterInventory's current shell. Validate and, if necessary, adjust only the native-overlay branch:

- Title: zero, one, and two-line modes.
- Curio font scale: minimum `50%`, default `110%`, maximum `150%`.
- Four stat rows: no collision with portrait, inner frame, item level, or card bottom.
- Item level: remains readable and inside the native inner border.
- Long localized Curio names: retain existing wrapping/ellipsis contract.
- Name It forced two-line Curio names: remain supported.

Do not globally move Character Overview text merely to accommodate the opt-in overlay. Store alternate offsets/sizes in the enabled branch so the disabled layout remains pixel-identical.

## Lifecycle, performance, and memory safety

- Blueprint work occurs when Darktide asks BetterInventory to create an entry widget, not in the per-frame update loop.
- Rarity synchronization occurs on init and item/data replacement only. It is constant time and allocates at most one four-number colour table per event.
- Reuse the native material path; do not load, cache, or unload textures manually.
- Continue using the native Curio init/update/destroy callbacks. BetterInventory must not assume ownership of icon render targets.
- Deep-clone native pass/style tables before modification. Mutating shared templates could leak the option into unrelated views or later widgets.
- Do not store widgets in module-level tables and do not register new event listeners. This avoids stale UI references and cleanup requirements.
- Avoid appending `inner_frame` more than once if the game or another mod already supplied it.
- Setting changes should use the existing view/layout refresh path. Do not layer new widgets over old ones in place.

There are no purchase or threading races in this feature. The relevant UI re-entrancy concern is repeated blueprint construction: every construction must start from fresh clones, be deterministic, and avoid modifying Darktide's source templates.

## Compatibility and edge cases

1. **Rarity strip disabled:** Curio strip remains hidden even though its colour is synchronized.
2. **Custom item background colour:** custom colour wins over rarity colour for both gradient and strip.
3. **No customization:** strip exactly follows `Items.rarity_color(item)`.
4. **Equipped Curio changes while view remains open:** `update_data` retints the existing widget.
5. **Missing or future rarity:** fail safely without indexing nil; retain the pass's existing fallback colour.
6. **Missing native template/pass:** log at diagnostic level if appropriate and retain the existing BetterInventory visual shell. Never prevent Character Overview from opening.
7. **Another mod changes native Curio passes:** locate by `style_id`, not array index.
8. **Inspecting another player:** preserve Inspect from Social and Inspect from Party Finder behavior.
9. **Empty/locked slot:** no detailed item is present; retain the existing native empty Curio blueprint and suppressions.
10. **Weapon cards:** no visual or behavioural regression.
11. **Native detailed Curios disabled:** the new overlay setting is greyed out and has no effect.
12. **UI scaling and aspect ratios:** verify Darktide logical-canvas behavior at common 16:9, 1440p/4K, and ultrawide resolutions.
13. **Localization expansion:** test long names and four-stat text with the largest font scale.
14. **Hot reload/setting toggle:** reopening or refreshing Character Overview must build exactly one frame and one icon pass.
15. **Coordinate regression:** centered title X is an additive `-1` delta, title width carries the horizontal inset, the favorite/checkmark Y remains around the primary toughness row after runtime synchronization, and the bottom-aligned item level uses a negative Y delta to move higher.

## Acceptance criteria

1. Every visible Curio rarity strip has a deliberate colour equal to its rarity or final custom background colour.
2. Turning **Show rarity colour strip** off hides Curio and weapon strips exactly as before.
3. The new option defaults off and does not alter existing profiles visually.
4. With the option on, populated detailed Character Overview Curios display Darktide's ornate inner frame and native-style portrait while retaining BetterInventory's title, four stats, and item level.
5. Empty slots, weapons, inventory grids, vendors, and inspection integrations do not regress.
6. No shared Darktide pass template is mutated, no render-target ownership changes, and no persistent widget references are introduced.
7. Native-overlay coordinate semantics are documented and guarded: centered title inset is expressed through width, marker Y is applied after runtime callbacks, and item-level Y uses the correct bottom-aligned sign.
8. All automated verification passes, followed by the in-game matrix above.
