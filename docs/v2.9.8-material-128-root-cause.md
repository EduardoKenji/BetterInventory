# v2.9.8 `material '128'` root-cause record

Date: 2026-08-22

## Finding

FirstFleet's full Crashify locals disambiguate the abbreviated error. `UIRenderer.create_material` received:

- `material_name = "content/ui/materials/frames/line_thin_dashed_animated"`
- `material_flags = 128`
- `style_id = "better_inventory_equipped_highlight"`
- `_element_view_id = "inventory_weapons_view_item_grid"`

The headline reported `Error loading material '128'`, but `128` was the renderer flag supplied as the third `Gui.create_material` argument. The missing resource was Better Inventory's static equipped-highlight frame, not a numeric icon-atlas value and not a custom weapon model.

## Why earlier containment was incomplete

v2.9.1 and v2.9.7 defend dynamic texture fields against numeric or malformed values. The crashing pass instead contained a valid, non-empty string, so those guards correctly preserved it.

Current Darktide source references `line_thin_dashed_animated` only from crafting recipe, perk, and trait UI components. Their view packages are preloaded in the Morningstar on supported platforms, which can hide the undeclared dependency. Psykanium and mission-preparation states can unload those hub packages while retaining the inventory view's own package, matching both reported reproduction paths.

## Remediation

- Equipped and newly acquired item highlight builders now use `content/ui/materials/frames/frame_tile_2px`, already used by Darktide's native item pass templates in the inventory grid.
- The uncertain one-pixel frame is normalized to the same inventory-owned frame.
- Material safety rewrites old dashed/one-pixel strings in stale hot-reload widgets before the draw call.
- Stored highlight mode IDs, colours, bounded layer counts, visibility rules, and the existing global-clock pulse remain compatible.
- No crafting package is loaded globally, avoiding a permanent package-memory cost and asynchronous load/unload lifecycle.
- No global `UIRenderer` or `UIPasses` hook is introduced.

## Evidence and limit

Regression tests cover source blueprints, normalized runtime `value_id_37` content, stale hot-reload values, all highlight modes, valid custom material preservation, and the absence of the retired dashed and one-pixel builder constants from card builders. The source and crash-local match is direct; a FirstFleet live retest in Psykanium and mission preparation remains the final engine-level confirmation.

## v2.9.9 scope correction

The v2.9.8 compatibility map also treated `frame_tile_1px` as uncertain. Subsequent user diagnostics showed that this was too broad: Darktide and DMF legitimately use that material, and generated native/third-party fields were being rewritten with visible warnings. v2.9.9 preserves `frame_tile_1px`, limits the unavailable dashed-frame migration to Better Inventory-owned highlight style IDs, and reports only genuinely malformed dynamic values.
