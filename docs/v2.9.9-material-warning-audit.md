# v2.9.9 material-warning audit

Date: 2026-08-24

## Report

A user saw repeated `Repaired unsafe UI material` warnings for generated widget fields including `value_id_36`, `value_id_48`, and `value_id_60` after installing v2.9.8. These names are pass indices assigned by `UIWidget.add_definition_pass`; they are not item, material, or backend identifiers.

## Cause

v2.9.8 correctly removed Better Inventory's unavailable `line_thin_dashed_animated` highlight dependency, but its stale-widget compatibility map also classified `content/ui/materials/frames/frame_tile_1px` as unsafe. Darktide and DMF use that one-pixel frame legitimately. Because the runtime guard also covers native and integration-provided inventory widgets, valid string values could be rewritten and announced once for each generated field.

## Correction

- `frame_tile_1px` is preserved as a valid native/DMF material.
- Only Better Inventory style IDs beginning with `better_inventory_equipped_highlight` or `better_inventory_new_item_highlight` may migrate the retired dashed frame.
- That known upgrade migration is silent because it is expected compatibility work, not malformed data.
- Numeric, table, empty, or missing dynamic materials remain repaired and retain one bounded warning per widget field.
- Valid unrelated native and third-party strings remain unchanged, including a third party's own dashed material reference.

The scope check is calculated once when a pass is guarded and captured as a boolean. No renderer hook, per-frame widget scan, retained widget registry, package load, backend request, or account mutation is introduced.
