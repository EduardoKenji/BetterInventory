# v2.9.9 material-warning audit

Date: 2026-08-24

## Report

A user saw repeated `Repaired unsafe UI material` warnings for generated widget fields including `value_id_36`, `value_id_48`, and `value_id_60` after installing v2.9.8. These names are pass indices assigned by `UIWidget.add_definition_pass`; they are not item, material, or backend identifiers.

## Cause

v2.9.8 correctly removed Better Inventory's unavailable `line_thin_dashed_animated` highlight dependency, but its stale-widget compatibility map also classified `content/ui/materials/frames/frame_tile_1px` as unsafe. Darktide and DMF use that one-pixel frame legitimately. Because the runtime guard also covers native and integration-provided inventory widgets, valid string values could be rewritten and announced once for each generated field.

## Correction

- `frame_tile_1px` is preserved as a valid native/DMF material.
- Only Better Inventory style IDs beginning with `better_inventory_equipped_highlight` or `better_inventory_new_item_highlight` may migrate the retired dashed frame.
- That known upgrade migration is silent because it is expected compatibility work, not malformed data.
- Numeric, table, empty, or missing dynamic materials remain repaired and retain one bounded warning per widget field.
- Valid unrelated native and third-party strings remain unchanged, including a third party's own dashed material reference.

The scope check is calculated once when a pass is guarded and captured as a boolean. No renderer hook, per-frame widget scan, retained widget registry, package load, backend request, or account mutation is introduced.

## Reporter mod-list compatibility follow-up

The reporter later supplied a 105-mod load order. The list was grouped by the surfaces that can interact with Better Inventory, and locally available or current upstream source was inspected for the highest-risk groups.

### Confirmed interactions

- **Extended Weapon Customization and its plug-ins:** EWC hooks `ViewElementGrid.present_grid_layout` and `_create_entry_widget_from_config`, and appends three texture passes to the shared gear-item template. Those extra passes can move Darktide's generated `value_id_*` numbers, which explains why the warning fields do not remain stable between mod lists. The inspected passes use built-in material strings and do not introduce `frame_tile_1px` or Better Inventory's retired dashed frame. Better Inventory loads after this stack in the supplied order, delegates through the existing hook chain, and guards the resulting widget.
- **Custom UI Colors:** its `InventoryView` integration enumerates existing widgets and writes colour arrays beneath known style paths. It does not replace texture-pass material names. A layout change can therefore produce a visual recolouring mismatch, but not this missing-material failure.
- **SimpleAssets and Resource Loader:** SimpleAssets resolves external textures asynchronously and exposes a texture handle as `userdata`; Better Inventory deliberately accepts non-nil `userdata` material references. Merely installing either resource library does not inject a material into an inventory card. A consuming mod must do that explicitly.
- **Character/loadout UI stack:** the supplied order places Psych Ward and Custom UI Colors before Improved Character Menu, EWC before Enhanced Character Selection, and the EWC community patches before EWC and its add-ons. Better Inventory follows the inventory/customization stack. No direct ordering defect was identified.
- **HUD, audio, outline, VFX, and 3D weapon customization mods:** these operate on HUD widgets, Wwise events, unit materials, particles, or attachment data rather than the `InventoryWeaponsView` texture-pass material field involved in the report.

### Remaining bounded uncertainty

- The exact `smaller_grid` source used by the reporter was unavailable. Because its name and placement imply an inventory-layout transformation, it is the first compatibility mod to isolate if a fresh v2.9.9 log still reports an inventory material problem.
- Type validation cannot prove that an otherwise valid third-party material string has a resource package loaded. A custom inventory extension could therefore supply a nonempty string that later fails inside `UIRenderer`. Replacing every unfamiliar string would break legitimate custom materials, so this path remains log-driven rather than globally rewritten.
- The EWC add-on collection is large and independently versioned. A plug-in built for a different EWC generation can corrupt its own attachment or item data, but no inspected current EWC path reproduced the reported frame warning.

### Independent stability confounder

The reporter runs `MemLeakFix`, `SMOG`, and `FpsDoctor` together. All three manage Lua garbage collection or cleanup scheduling. Their simultaneous use can create redundant collection work, frame stalls, and last-writer-wins GC tuning. This is not a plausible source of the `frame_tile_1px` warning, but the three should be disabled together during a clean crash-isolation run and then reintroduced one at a time.

### Diagnostic decision

No broader v2.9.9 material rewrite is justified by this mod list. The safe next evidence boundary is a full console log produced by v2.9.9:

1. Confirm the runtime version is 2.9.9. The obsolete `Repaired unsafe UI material` wording identifies v2.9.8 code; v2.9.9 uses `Repaired invalid UI material field` only for genuinely malformed values.
2. If the problem remains, test without the three overlapping garbage-collection mods.
3. Isolate `smaller_grid`, followed by the EWC add-on set, while retaining the same item and reproduction steps.
4. For a renderer crash, retain the Lua locals containing the material value, `style_id`, widget name, and view. These distinguish a malformed value from a valid but unloaded third-party resource.

The focused material and layout suites pass after this review. The repository verifier also confirms 43 behavior-test files, 165 named cases, current and legacy DMF/Alf contracts, runtime manifest version 2.9.9, and local release-archive parity.
