Date: 2026-09-30. Baseline: tag `v3.6.0` at
`d25d8af54518f9c34f4489a07b057e3fb56cd31d`. Target: the current `v3.7.3`

Game reference: local Darktide 1.13.0 source at `419fe18d4` (September 29).

## Finding fixed

**Curio consecration could dispatch after a silent DMF save failure.** The
installed DMF catches errors from `Application.set_user_setting`, logs them,
and returns no success/failure status. The previous worker assumed that a
non-throwing call to `save_unsaved_settings_to_file` had saved its recovery
record. A serialization failure, including one caused by another mod's settings,
could therefore allow an upgrade without the updated restart-recovery record.

The shared persistence function now reads the journal back through
`Application.user_setting` and compares it using native `table.equals` before
allowing progress. A mismatch stops the worker before dispatch. This covers
enqueue, reconciliation and pre-upgrade journal updates through one function.
It verifies the engine settings state after the save request; it cannot guarantee
physical disk durability during an OS crash or power failure.

The regression reproduces DMF's silent-return behavior. It failed before the
fix with `silent save failure dispatched an upgrade`, and passes afterward.
Existing throwing-save, ambiguous-write, restart, reload, account ownership,
funds and cancellation checks continue to pass.
