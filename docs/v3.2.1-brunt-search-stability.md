# v3.2.1 Brunt search stability audit

## Outcome

Equipment Text Search is disabled specifically for Brunt's Armoury by default. On a fresh view initialization, Better Inventory does not add the search widget, search-row padding, runtime state, input ownership, filtering, or ranking. The global Equipment Text Search setting continues to control every previously supported inventory and vendor view.

Users who opt in must reopen Brunt's Armoury because Darktide constructs the view scenegraph and grid geometry during initialization. Disabling the option while an already decorated view remains open immediately hides and defocuses the field and releases its search runtime; reopening removes the reserved row as well.

## Flicker root cause

Darktide's `CreditsGoodsVendorView`, used by Brunt's Armoury, deliberately defines no native sort options. Better Inventory's identity-preserving search lane previously required a native sort function. When none existed, it fell back to `_present_layout_by_slot_filter`, whose native grid presentation destroys and recreates the weapon-family button widgets. Every settled query therefore made all Brunt buttons disappear and reappear.

The fallback was not a leak in the query parser or projection cache. It was an unnecessary full grid presentation caused by treating “no native comparator” as an unsupported in-place grid.

## Fix contract

When Brunt search is explicitly enabled, the in-place lane now supplies one retained search-only comparator:

1. Higher search relevance ranks first.
2. Equal ranks retain their canonical source-grid order.
3. Existing entry tables, widget records, selection identity, alignment anchors, and the canonical `_grid_layout` remain owned by Darktide.
4. Two bounded layout buffers prevent the live grid from observing a buffer being cleared for the next query.
5. One retained source-position map is cleared and reused; ordinary queries allocate neither a comparator closure nor replacement widgets.
6. A mod hot reload replaces only the cached comparator closure if its captured runtime generation changed.

Views with a native or ItemSorting comparator continue using it unchanged. The fallback is used only when a supported live grid has no callable selected comparator.

## Acceptance coverage

- Brunt option absent or false: no widget definition and no added geometry.
- Brunt option true: search UI is decorated after reopening.
- Disabled Brunt presentation: no search capture; any stale runtime is released.
- No-sort in-place reorder: matched entry moves first, canonical anchors remain positioned, existing widget identity is retained, and no authoritative presentation fallback is needed.
- Existing Inventory, Hadron, Armoury Exchange, GlobalStore, and Melk search paths retain their prior comparator behavior.
