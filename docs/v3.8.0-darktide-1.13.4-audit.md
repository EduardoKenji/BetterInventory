# BetterInventory 3.8.0 — Darktide 1.13.4 compatibility audit

Reference: `Darktide-Source-Code` at `e46b8926c` (1.13.4, 2026-10-22), compared
against the previous audit baseline `419fe18d4` (1.13.0, see
[v3.7.2 audit](v3.7.2-compatibility-performance-audit.md)). The range covers
1.13.2, 1.13.3 and 1.13.4: 162 files changed.

## Method

1. Listed every game script changed in the range.
2. Intersected it with BetterInventory's `require` paths, `mod:hook*` targets
   (including class-name strings) and game file basenames referenced in runtime
   Lua.
3. Read each intersecting diff and checked every `Items.*` / `Text.*` function
   BetterInventory calls still exists with a compatible signature.

No view BetterInventory hooks was renamed or removed. The heavily changed
`inventory_weapon_cosmetics_view`, `view_element_session_stats`,
`mission_board_view` and `live_events_view` are not referenced.

**Edge case noted, not a regression:** the native view's mark switch now removes
a weapon skin that is incompatible with the new mark. The Auto Crafter switches
marks through `Managers.data_service.mastery:switch_mark` directly, so it does
not get that cleanup. It only switches freshly crafted Brunt weapons, which
carry no skin, so there is no current impact. Revisit if mark switching is ever
offered for owned, skinned weapons.

## Fixes shipped with this audit

- **Character Cosmetics View Improved** (planetbrown). CCVI writes unowned
  preview cosmetics into `_preview_profile_equipped_items` with `__locked = true`
  and a `math.uuid()` gear id. Native `_equip_local_changes` sent them to the
  backend, one fake id rejected the whole batch, and BI's bounded retry then
  reported "Failed to persist loadout". `EquipmentPersistence` now restores
  the owned starting item for any `__locked` / `__is_preview_item` slot before
  native equip runs. Test: `test_equipment_persistence.py` `unowned_preview_filtering`.
- **Auto Crafter sibling mark** (joblauder). `combatsword_p3_m3` (Duelling
  Sword Mk V) has `defence_stat` where `p3_m1/m2` have `cleave_damage_stat`.
  Brunt's family offer can return a sibling mark, so a missing dump stat is now
  a miss (infinite distance) instead of a terminal failure. First-weapon mode
  will not accept such a roll. Test: `sibling_mark_missing_dump_stat_is_a_miss`.
- **Auto Crafter docket cap** (CrinkleSnap). By design the cap bounds target
  acquisition only, so fallback runs bought mastery fodder past it. New opt-in
  setting `auto_crafter_docket_cap_includes_mastery` (default off) makes it
  bound the whole run. Test: `docket_cap_bounds_post_target_fodder` (both values).
- **Games Lantern 403** (reisei). Cloudflare now rejects curl's default
  User-Agent. Both curl adapters send a fixed, descriptive
  `BetterInventory-Darktide-Mod (+nexus URL)` agent.
  - The community patch (`patched_transport_win.lua`) was reviewed. Its only
    change is a constant spoofed Chrome UA passed with `-A`. No input reaches
    the shell, so it is safe.
  - The patch was not adopted for two reasons. Impersonating a browser is
    brittle, because Cloudflare also checks the TLS fingerprint. And it only
    fixed Windows, not the Wine/Proton adapter.
  - **Live acceptance is pending.** If the honest agent is still challenged,
    ask Games Lantern for an allow-listed agent or an API rather than spoofing.

## Best-practice review (follow-ups, not in 3.8.0)

Reviewed against the DMF hooks wiki, DMF source, Lua Performance Tips and the
LuaJIT NYI list. BI already follows most of these practices:

- centralised teardown on `on_disabled`/`on_unload`;
- no `hook_origin`;
- `allow_rehooking` set;
- per-frame update gated by `needs_update()`;
- the draw overlay uses `hook_safe` behind a cached gate.

Gaps, ranked:

1. **Unprotected `mod:hook` handlers (M).** DMF does not pcall `mod:hook`
   handlers, unlike `hook_safe`. Several BI hooks run substantial logic around
   `func`, for example `ViewElementGrid.present_grid_layout`,
   `ItemGridViewBase.init` and `InventoryWeaponsView._handle_input`. A shared
   guarded-hook helper should pcall BI's part and fall through to `func`.
2. **Hard `require` of 16 game view files at load (S).** A renamed file stops
   the whole mod from loading. Use `pcall(require, ...)`, and let
   `ensure_class_method` skip hooks on a nil class.
3. **Unguarded hooks (S).** A few hooks skip `ensure_class_method`. DMF only
   logs a missing method, so a patch would cause silent feature loss. Examples:
   - `MainMenuView`;
   - `CreditsVendorView.on_enter`;
   - `_update_window_size`;
   - `_cb_on_sort_button_pressed`.
4. Lower value:
   - an audit of promise chains ending in `:catch`;
   - an accessor module for the most-used private view fields;
   - splitting `BetterInventory_runtime.lua` hook registration.

## Follow-up audit rounds (same release)

Four further read-only audits ran: Auto Crafter + Games Lantern, UI/runtime,
curio/discard/persistence, and the modules not previously reviewed (search,
WKC/GSC integrations, settings, panels, localization). A separate pass
re-validated every v3.8.0 change for all configurations. Fixed in 3.8.0:

- Curio scan aborted by an undefined `MAX_OFFER_ERROR_LOGS_PER_SCAN` global
  (declared in another module). `check_lua_structure.py` now rejects ALL_CAPS
  constants read without a declaration in the same file.
- Search hooks on `ItemGridViewBase` never reached concrete views, because
  `class()` copies superclass methods at definition; dynamic forwarders fix it
  and also keep BI's hook in the chain when MaxStatMark hooks the subclasses.
- Customized items protected from discard; manual discard fails closed on
  unreadable presets; curio favorites written for the purchase character.
- Auto Crafter: fail fast when the selected mark lacks the dump stat; never
  reuse a favorited Transcendent level-500 build (except this session's
  interrupted run); release aux-only quarantine; reset stale Phase 4 state.
- Empty character roster no longer persists a Classes targeting fallback.
- 9 code fallbacks aligned with `BetterInventory_data.lua` defaults.
- Grid selection guarded on unpresented grids (controller focus crash).
- WKC per-instance icon material and scale honoured.
- Localization gaps (missing en key, corrupted zh-CN tooltip, zh-CN globals).
- About 480 lines of AST-verified dead code removed.

Deferred, with rationale (not regressions):

- Manual discard lease released before a delete chained behind pending equips
  (needs adoption of the native delete promise; medium complexity).
- Consecration queue head-of-line blocking on an uncertain entry.
- Automatic discard does not see unsaved preview equips.
- Phase 4 mark switch happens after material spend; no pre-check that the
  target mark is unlocked when mastery leveling is off.
- Planner estimates ignore per-mark stat asymmetry (runtime handles it).
- Controller-focus bypass of `_handle_input` skips vendor tab bumpers.
- Per-frame WKC logic pass and search fingerprint cost (measured cost unknown;
  optimise after profiling in game).
