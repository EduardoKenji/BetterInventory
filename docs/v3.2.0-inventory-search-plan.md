# v3.2.0 Inventory Search research and implementation plan

## Decision

Better Inventory can provide a standalone inventory search feature without depending on Stuff Searcher. The implementation should be original and use current Darktide filtering contracts rather than porting Stuff Searcher's layout mutation.

The first v3.2.0 implementation should be read-only: it may rank, dim, or hide presented entries, but it must not favorite, equip, purchase, discard, sacrifice, or modify an item. Search must compose with native slot filters and the active native or ItemSorting comparator.

The default unmatched-card behavior is **Dim and promote matches**. Every entry remains available, matching entries form the highest-priority sort group, and unmatched cards receive a lightweight widget-level fade. A dropdown also offers **Hide unmatched**, which uses the native filter path. An empty query applies neither behavior and must be presentation-identical to v3.1.0.

## Why Stuff Searcher stopped working

Stuff Searcher 1.2 does not have a reusable query engine. `search.lua` contains empty function stubs; the behavior is implemented directly in `stuff_searcher.lua` as view mutation and input handling.

The principal break is structural:

1. It copies `view._filtered_offer_items_layout` once into `view._stored_layout`.
2. It filters that snapshot into another table.
3. It writes the result back to `view._filtered_offer_items_layout`.
4. It asks the view to sort and present the replaced table.

Current Darktide no longer owns `_filtered_offer_items_layout`. `ItemGridViewBase._present_layout_by_slot_filter` now reads the live `view._offer_items_layout`, applies native slot/type filtering plus `_filter_by_filter_option`, and passes the resulting table to `_sort_grid_layout`. Replacing the removed field therefore has no effect.

Even before that field was removed, the design had additional correctness and compatibility problems:

- The one-time `_stored_layout` becomes stale after a purchase, discard, item replacement, store rotation, asynchronous inventory refresh, or tab change.
- The search input and active view are stored globally on the mod, allowing one view's state to leak into another view or a hot reload.
- Search strings are rebuilt with repeated localization and MasterItems lookups for every item on every changed query.
- Only `%` is escaped before `string.find` uses Lua-pattern mode. `.`, `+`, `-`, `*`, `?`, `[`, `]`, `(`, `)`, `^`, and `$` remain pattern syntax and can mis-match or error.
- The non-English helper is declared local inside an initialization block, then referenced outside that scope. This produces the reported `localize_en` nil error.
- It temporarily hooks `LocalizationManager.init` and manually constructs a second manager, which is unsafe global lifecycle ownership for a search feature.
- It scans raw keyboard keystrokes every frame and hard-codes `S`, rather than using a configurable input action and view-local focus ownership.
- It globally changes `ViewElementGrid`, `ViewElementTabMenu`, and `ViewElementInputLegend` behavior while one global textbox is active.
- Empty results require unrelated preview/equip guards because the filter is applied outside the native selection lifecycle.
- Curio and perk text uses localized descriptions as an unstructured pattern corpus. Percent values therefore collide with Lua pattern syntax and numeric searches are substring-based.
- The community `&` patch is not present in the 1.2 archive and splits strings with another Lua pattern. It supplies useful behavior, but not a bounded parser.

These defects also explain the historical Stuff Searcher conflicts with Inventory2D and ItemSorting. The feature changed the layout and then separately called sorting, so whichever mod owned the last private-field or comparator assumption won.

## Current Darktide seams

### Standard inventory and vendor views

`ItemGridViewBase._present_layout_by_slot_filter` is the authoritative composition point for:

- `InventoryWeaponsView`;
- `CreditsVendorView` and its Armoury/GlobalStore routes;
- `MarksVendorView`;
- `CraftingMechanicusModifyView`.

Its order is:

1. read the current `_offer_items_layout`;
2. apply slot and item-type filters;
3. call `_filter_by_filter_option(entry)`;
4. pass the filtered copy to `_sort_grid_layout`;
5. preserve the selected gear ID while re-presenting.

In **Hide unmatched** mode, Better Inventory should chain `_filter_by_filter_option`:

```lua
return original_native_filter(view, entry) and Search.matches(view, entry)
```

In **Dim and promote matches** mode, `_filter_by_filter_option` returns the original native result without removing unmatched entries. The precomputed match bit becomes the outermost Better Inventory comparator key instead. The comparator must only read cached booleans; it must never localize, project, parse, or allocate while `table.sort` is running.

The wrapper around `_present_layout_by_slot_filter` should record the latest slot filter, item-type filter, and display name in view-local state. When the query changes, it can call the same native method with those captured arguments. Darktide then rebuilds from the current `_offer_items_layout`; Better Inventory never snapshots or replaces the source.

This ordering also gives ItemSorting its expected `optional_filter_layout`. In hide mode, ItemSorting receives only matching entries. In dim mode, it receives the full natively eligible layout and orders entries inside the matched and unmatched groups. Better Inventory must add the search key to its existing comparator wrapper instead of wrapping the same comparator a second time.

### Hadron sacrifice view

`CraftingMechanicusBarterItemsView` owns a separate `_item_grid_layout` and `_sort_grid_layout` implementation. It needs a small explicit adapter rather than pretending it follows `ItemGridViewBase`'s optional-filter contract.

The adapter must:

- keep the authoritative `_item_grid_layout` untouched;
- build a filtered presentation copy from that live table;
- preserve external spacing entries in their native positions;
- consume the layout after the selected native comparator, then apply one stable match partition before the native presentation callback;
- rebuild after sacrifice-state, mastery-pattern, selection, and inventory changes;
- release the copy and search index when the view closes.

This adapter should land only after its lifecycle tests pass. It must not temporarily replace `_item_grid_layout` around a native call because an error or asynchronous callback could strand the filtered copy as the source of truth.

## Proposed v3.2.0 feature surface

### Simple search

Plain text searches a normalized literal corpus. Search is case-insensitive through `Utf8.lower`, and `string.find(..., 1, true)` must always use literal mode.

The corpus should include, when available:

- Better Inventory custom name and imported Name It name;
- localized weapon family, pattern, and mark;
- localized Curio/item name;
- blessing names;
- perk names, canonical Darktide descriptions, and both Better Inventory compact-description forms;
- localized effective rarity and item type;
- stable master-item, trait, localization, and mark identifiers as fallback aliases;
- visible total and base ratings as discrete numeric fields.

Do not call a hookable full weapon-name/stat projection for every item. In particular, indexing must not invoke GodRolls' decorated-name calculation. Resolve native localization IDs directly, then add Better Inventory's stored custom name explicitly.

### Effective rarity and native rarity

Search must treat Better Inventory's `Sainted` presentation tier as distinct from Darktide's stored `Transcendent` rarity.

Darktide stores ordinary quality in `item.rarity`: `1` Profane, `2` Redeemed, `3` Anointed, `4` Exalted, and `5` Transcendent. Better Inventory's Custom legendary tier does not mutate that value. When the feature is active and `CustomTier.matches(item)` accepts a rarity-5 weapon or Curio, `Items.rarity_display_name` instead presents native localization tier `6`, currently `Sainted` in English.

The search projection therefore carries two fields:

- **effective rarity**: what the player currently sees. A qualifying custom-tier item is `Sainted`; a non-qualifying rarity-5 item is `Transcendent`;
- **native rarity**: the underlying Darktide value and label. Both of those items remain native `Transcendent`/`5`.

Plain rarity words and the `rarity:`/`quality:` fields use **effective rarity**. Consequently:

```text
sainted                 -- only currently qualifying Custom legendary tier items
transcendent            -- only visible Transcendent items, excluding Sainted items
rarity:sainted          -- same explicit effective-tier filter
rarity:transcendent     -- same explicit effective-tier filter
native-rarity:transcendent -- every stored rarity-5 item, including Sainted items
```

An exact bare clause equal to a known localized rarity name or built-in English rarity alias compiles as a rarity predicate, so `Sainted`, `Anointed`, or `Redeemed` means “only this effective rarity,” not “this text appears somewhere.” A custom item name containing one of those words remains searchable with `name:sainted`. Partial text such as `saint` may still use the normal literal corpus.

Current-locale rarity labels come from `RaritySettings` localization keys. English aliases are a small static table for cross-locale usability; search must not recreate the removed Stuff Searcher `localize_en` lifecycle. Numeric native values are accepted only by `native-rarity:` to avoid conflating visible and stored tiers.

The effective tier must be derived from the same active `CustomTier.matches` provider used by presentation, independent of which mod owns background colors. Disabling Custom legendary tier makes `Sainted` match nothing and returns all stored rarity-5 items to effective `Transcendent`. Any custom-tier enable/criteria change invalidates the affected search projections and requests one coalesced refresh.

### Explicit AND

`&` separates required clauses outside quotes:

```text
power & cycler
dueling & riposte & uncanny
name:"power sword" & blessing:cycler
```

Whitespace around `&` is optional. Empty clauses are ignored. A quoted `&` remains literal.

### Field-qualified clauses

Initial aliases:

| Canonical field | Accepted examples |
| --- | --- |
| `name` | `name:plasma`, `name:"dueling sword"` |
| `blessing` | `blessing:uncanny`, `bless:cycler` |
| `perk` | `perk:carapace`, `perk:flak`, `perk:"flak dmg"` |
| `type` | `type:melee`, `type:curio` |
| `mark` | `mark:iv` |
| `rarity` | `rarity:sainted`, `rarity:transcendent`, `quality:anointed` (effective visible tier) |
| `native-rarity` | `native-rarity:transcendent`, `native-rarity:5` (underlying Darktide tier) |
| `rating` | `rating:500`, `rating:>=490`, `rating:480..500` |
| `base` | `base:380`, `base:>=370` |
| `favorite` | `favorite:true` |
| `equipped` | `equipped:true` |
| `new` | `new:true` |

Unknown field names should be treated as literal text in simple mode, not as a fatal parse error. OR, nested groups, arbitrary Lua patterns, user scripts, and separate quick-filter controls are out of scope. State and type conditions remain available through the text fields above without duplicating Better Inventory's existing inventory controls.

### Unmatched-card behavior and sort hierarchy

The unmatched-card behavior is selected in Better Inventory's Mod Options:

| Value | Behavior |
| --- | --- |
| `Dim and promote matches` | Default. Matching cards move above every unmatched card. Unmatched cards remain interactive and receive a uniform fade. |
| `Hide unmatched` | Non-matching entries are removed through Darktide's native filter composition. |

Within the currently selected native tab/type, ordering is strictly:

1. search match group, when a non-empty query is active;
2. for Curio primary/secondary text matches, equipped primary+secondary, equipped primary-only, equipped secondary-only, non-equipped primary+secondary, non-equipped primary-only, then non-equipped secondary-only when equipped/favorite priority is enabled;
3. Better Inventory equipped/favorite priority for ordinary matches and ties;
4. Better Inventory perfect-roll priority;
5. the selected ItemSorting or native Darktide comparator.

Partial literal clauses use the same Curio hierarchy, so `heal` ranks Health primary and secondary lines exactly as `health` does. A Curio matched only by its name or another property remains in the ordinary matched group. Every unmatched entry shares rank zero and therefore retains the complete pre-search hierarchy.

Search never overrides native tab, slot, item-type, ownership, or store eligibility. A matching ranged weapon cannot appear in a melee or Curio tab.

The search rank must be a separate comparator decision, not a large numeric offset added to the existing priority. Its bounded Curio relevance values are computed once during the projection scan and read in O(1) by the comparator. If both entries have the same relevance rank, the existing Better Inventory and downstream comparator behavior executes unchanged. When the query is empty, all entries have the same search rank and the wrapper is behavior-neutral.

Use `widget.alpha_multiplier` for the default fade. Darktide's `UIWidget.draw` already multiplies this scalar across the entire card, including its background, image, icons, and text. This preserves custom colors and avoids cloning or rewriting every pass style. A value near `0.40` is the initial live-QA target. `color_intensity_multiplier` may be tested as a small companion adjustment, but true grayscale is out of scope because it would require per-pass color ownership or a custom material/shader.

Dimmed cards remain clickable, focusable, and inspectable. The right detail panel remains at full opacity. Hide mode changes only list membership, not any account or item state.

### Search UI

The in-view UI should contain only one compact text field. Supporting behavior remains in Mod Options:

- the unmatched-card behavior setting;
- a **Remember searches during this game session** option, defaulting to Off;
- a configurable focus input action, defaulting to Off until a conflict-free action is selected;
- Escape to defocus the field first, then allow the normal view exit on the next press;
- controller Up from any first-row item moves focus into the field, Confirm invokes Darktide's native text-entry path (including Xbox/PlayStation virtual keyboards), and Down returns to the current result grid's first item without suppressing unrelated grid, tab, purchase, equip, compare, or legend input.

The widget must be created from Better Inventory's per-view cloned definitions or a Better Inventory-owned view element. It must not mutate the shared module definition table returned by `hook_require`.

When a result disappears, native gear-ID selection restoration should choose the same matching item when possible or the first valid result. Hide mode may present an empty native grid, without patching preview or equip functions.

### Query lifetime and optional session memory

By default, query text remains active while the current view is alive, including item selection, tab changes, sorting changes, native re-presentation, store refreshes, and crafting replacement. Closing that view clears the query. This is the least surprising default for **Hide unmatched**, because a later reopen cannot appear empty due to a forgotten filter.

When **Remember searches during this game session** is enabled, Better Inventory retains only the bounded query string after a view closes. The record is keyed by the active character and logical view family so an Inventory query is not silently applied to Armoury/Requisition, Hadron, or Melk. Reopening the same family for the same character restores the text, compiles a fresh query, and matches the current authoritative layout.

Session memory never stores a compiled query, closure, widget, view, layout, item table, match result, or projection cache. Clearing the text replaces the remembered record with an empty query. Character change, mod disable, Ctrl+Shift+R hot reload, and game exit clear all remembered searches. The existing unmatched-card behavior dropdown remains an ordinary mod setting and is not duplicated into session memory.

## Proposed module boundaries

| Module | Responsibility |
| --- | --- |
| `BetterInventory_search_query.lua` | bounded tokenizer/parser, literal normalization, numeric comparator compilation |
| `BetterInventory_search_index.lua` | fail-soft extraction of searchable item fields and bounded per-item cache |
| `BetterInventory_search_runtime.lua` | view-local state, native-filter composition, refresh scheduling, view adapters |
| `BetterInventory_search_ui.lua` | cloned definitions, compact text-field geometry, focus, and input ownership |
| `BetterInventory_search_hooks.lua` | isolated native-grid, input, focus, and Hadron sacrifice hook ownership |

`BetterInventory_features.lua` exposes only the composition facade. Search-only hooks live in `BetterInventory_search_hooks.lua`; this preserves the repository's single-hook-owner rule and keeps `BetterInventory_runtime.lua` below its 100 KB architecture ceiling.

## Implementation status

The v3.2.0 branch now implements the complete first-release scope:

- bounded literal parser, quoted `&`, typed fields, numeric comparisons, and fail-open invalid input;
- weak, fingerprinted projections for current-locale native/custom names, family/mark, perks, blessings, ratings, state flags, and split effective/native rarity, including Simplified Chinese UTF-8 names, trait descriptions, and rarity labels;
- search-first stable ranking with cached Curio primary/secondary relevance over the existing equipped/favorite, perfect-roll, and ItemSorting/native hierarchy;
- default dim-and-promote behavior, optional hide behavior, and one compact query field placed with independently configurable Inventory/Armoury top and bottom padding below native headers; defaults are Inventory `14 / 46` and Armoury `22 / 34` (top / bottom) without changing native titles;
- a search-owned top mask inset that clips scrolled cards below the field while preserving each grid's native bottom edge, plus a CreditsVendorView post-update flush shared by Armoury Requisition and GlobalStore;
- per-character/view-family session memory (default Off), optional keyboard focus action, first-row controller focus transfer, Escape-first defocus, and card-selection defocus without query clearing;
- current-contract adapters for Inventory, Hadron modify, Armoury/Requisition, GlobalStore/general vendors, Melk, and the separate Hadron sacrifice grid;
- per-view cloned definitions, missing-geometry fail-open behavior, 80 ms coalescing, generation-stamped weak relevance ranks, alpha ownership restoration, and explicit close/hot-reload release;
- direct custom-name invalidation, dynamic favorite/equipped/new/loadout fingerprints, GodRolls/God Stat Checker presentation isolation, and one bounded Stuff Searcher compatibility warning.
- production master-item perk paths resolve through their gameplay trait IDs before compact-label lookup; every trait/perk identity is projected first, compact perk aliases next, and optional long descriptions last, so Enhanced Descriptions cannot starve `flak`, `unyielding`, or later perk slots from the bounded record.
- the finalized performance path warms cold rich projections in bounded 16-item slices, defers parsing and matching until 80 ms of quiet, then trusts those validated records for one scan; it reuses one scan context, stores the bare-text corpus as one bounded string, coalesces one commit, skips repeated input, encodes match and Curio relevance in one rank map, and stores dim ownership as scalar alpha values.
- dim mode now rebinds the active comparator after any ItemSorting replacement and uses Better Inventory's proven deferred resort lane instead of rebuilding every widget; hide mode retains native filter presentation and reuses the just-computed results during its capture hook.

### Final performance audit

`tools/benchmark_search.py` now uses Darktide-shaped `{ item = item }` entries and 128 realistic weapon projections containing long Enhanced Descriptions blessing text plus two searchable perks. Ten final dim/hide runs report all 128 records built once in eight bounded slices, all 128 reused by the settled query, `0-1 ms` total for a synthetic burst of 400 text changes, `0-1 ms` for the one settled match pass, and about `8.55 KiB` transient allocation for that pass. Windows `os.clock` has millisecond granularity, so these absolute sub-millisecond figures are regression indicators rather than engine-frame promises.

The final 128-item projection state is approximately `415.3 KiB`; explicit release and full collection reclaim approximately `413.3 KiB`, with no positive retained delta. Six thousand settled idle frames take `0-1 ms` in aggregate (`0-0.167 microseconds` reported average), perform no item projection or layout presentation, and allocate no search state. Cache warming totals `13-15 ms` in this synthetic runtime but is divided across eight frames; no frame processes more than sixteen rich projections. Real input-string allocation belongs to Darktide's text widget and is intentionally excluded from the 400-change runtime transaction measurement.

Correctness is retained by separating cache trust from validation: only a query edit may use `trust_cache`; native presentation capture, store/inventory composition, refresh, and explicit invalidation still calculate the full item/customization/state fingerprint. Custom-name, tier, favorite/equipped/loadout, crafting, purchase, discard, and view lifecycle callbacks retain their existing invalidation or presentation paths. The runtime still fails open on projection failure and keeps all caches weak and view-owned.

The automated release gate passes all 50 behavior scripts. Search core modules meet their configured risk-weighted Lua coverage thresholds. Version metadata, generated manifests, and release packaging are complete. Remaining release work is live visual/gamepad QA.

## State, cache, and performance rules

- State is keyed weakly by view; there is no global active view or global input widget.
- Optional query memory is a separate bounded table of plain strings keyed by character and logical view family; it contains no live view or item references.
- View cleanup is registered with `BetterInventory_view_session.lua` and repeated from `on_exit`/`destroy` fail-soft paths.
- Compile a query only after its text has remained unchanged for the 80 ms quiet interval.
- Match a compiled query without concatenating new strings per entry.
- Empty-query presentation starts a bounded cache warmer that validates at most sixteen rich item projections per frame and retains no layout snapshot. A query may use the same slices while its quiet deadline is pending; the full match pass never shares a frame with the final cold-projection slice.
- Text changes update only the bounded source string and one numeric deadline. Copy/paste, deletion, and rapid typing allocate no parser, projection, match, timer, promise, or result table until the final text settles.
- Match results use generation stamps plus one weak-key numeric rank map; rank zero means unmatched, while positive values encode ordinary or Curio relevance. Reuse the same maps instead of allocating a result table for every character.
- Existing widgets are updated once after the settled scan. Dimming is one scalar write to `widget.alpha_multiplier`, not a clone or per-pass style rewrite.
- Reordering or hiding is coalesced through one view-local pending timestamp. Dim mode requests one post-update comparator resort; hide mode performs one native filter presentation. Continuous typing performs neither.
- Paste, clear, and dropdown changes use the same coalesced commit path.
- Cache projections by item identity plus a bounded fingerprint of relevant revision, name, rarity, ratings, traits, perks, and customization revision.
- Invalidate on item replacement, purchase, discard/sacrifice, inventory/store refresh, custom-name change, locale/master-item generation change, and mod re-enable.
- Bound query length, clause count, aliases per field, and projected text length. Proposed initial limits: 128 UTF-8 characters, 16 clauses, and 2 KiB normalized text per item.
- Do not retain full item tables in a process-lifetime cache. View caches must be weak or explicitly released.
- During the first bounded warm-up window, idle update projects at most sixteen records. Once warm, per-frame idle cost is limited to checking the input revision and pending-commit timestamp; there is no layout scan, localization, comparator rebuild, alpha scan, or allocation.
- A changed query should scan the active source once. A 200-item inventory and repeated search/clear cycle must remain bounded in the automated soak.
- Dim mode still draws unmatched cards, so it does not claim a GPU/render-count reduction. Its benefit is visual context and cheap presentation state. Hide mode reduces the final widget/draw count after the coalesced native re-presentation.

## Compatibility rules

### ItemSorting

- Native and ItemSorting filtering/sorting order is preserved. Hide mode uses native filter, Better Inventory search predicate, selected comparator, presentation. Dim mode uses native filter, search-rank key, Better Inventory priorities, selected comparator, presentation.
- Search must pass the native or filtered copy as `optional_filter_layout`; it must not invoke a second standalone sort.
- Search rank is incorporated into the current Better Inventory comparator manager. Comparator wrappers remain owned by the current Better Inventory sorting domain.
- Rebinding after ItemSorting enable/disable or option changes must preserve the search key exactly once and preserve the selected comparator by display identity.

### Better Inventory custom names and colors / Name It

- The effective stored custom name is searchable.
- Searching never changes name or color ownership.
- A name edit invalidates only that item's search projection and requests one deferred refresh.

### GodRolls and God Stat Checker

- Search does not ask either mod to calculate names, grades, or full stat projections.
- Existing visible third-party colors remain presentation concerns and are not rewritten.
- Optional future grade filters require a guarded provider contract; they must not scrape decorated visible strings.

### Stuff Searcher and DumpStatFinder

- Better Inventory does not write another mod's settings or disable another mod.
- If Stuff Searcher is enabled, show one bounded compatibility warning recommending that its search UI be disabled or removed. Its obsolete layout mutation can still hide or replace entries after Better Inventory's native filter.
- If another mod already supplies a native filter function, Better Inventory calls the existing chain first and adds its own predicate with AND semantics.
- Search UI placement must not assume another mod left native scenegraph geometry untouched. Missing geometry disables only the UI for that view; filtering remains fail-soft and must never crash the view.

- missing, partial, throwing/metamethod, and version-drifted item fields;

- sort comparisons perform only O(1) cached match/priority reads and allocate nothing;
- 100 search/clear cycles do not grow view/cache counts;

- fully warmed and settled idle update performs no O(n) scan or allocation;
