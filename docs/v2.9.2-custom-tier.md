# BetterInventory v2.9.2 custom-tier design

## Reference behavior

The locally installed Red Weapons At Home 1.2.6 implementation was inspected as the compatibility reference. Its defaults are:

- primary colour `{255, 210, 30, 40}` (ARGB);
- dark colour at 60% of each RGB channel;
- only rarity-5 (Transcendent) items are eligible;
- melee and ranged weapons require `Items.expertise_level(item, true) == Items.max_expertise_level()`, currently Power 500;
- Curios require their primary roll to reach the current maximum: 21% Health, 17% Toughness, 3 Stamina, or 1 Wound;
- each Curio type has a minimum Power control defaulting to zero; and
- qualifying items use Darktide's native `loc_item_weapon_rarity_6` display name.

BetterInventory reproduces those defaults but does not import, call, or require Red Weapons At Home.

The colour section includes DMF's native live preview. Editing the preview updates the RGB channels and selects Custom; choosing a preset or moving an RGB slider updates the preview without polling.

## Configurable classification

All criteria are applied only to Transcendent items. Melee and ranged weapons have independent controls for:

1. minimum displayed Power;
2. minimum total of all base modifiers, where zero disables the filter;
3. minimum value required from every base modifier, where zero disables the filter;
4. the number of modifiers that must meet a high-stat threshold, where zero disables the filter; and
5. the value of that high-stat threshold.

Health, Toughness, Stamina, and Wound Curios each have an enable switch, minimum primary roll, and minimum displayed Power. Curio values are resolved through BetterInventory's existing gameplay-data-backed `BetterInventory_curio_values.lua` adapter rather than localized description parsing.

Missing item type, rarity, Power, base modifiers, primary trait, or resolved Curio value fails closed whenever the corresponding criterion is required. The feature is presentation-only and never modifies item rarity, gear, favorites, loadouts, or account data.

## Red Weapons At Home compatibility

Red Weapons At Home directly replaces `Items.rarity_color` and `Items.rarity_display_name`. BetterInventory installs its final wrapper after all mod scripts load, making load order deterministic.

When both features are active, BetterInventory wraps Red Weapons At Home's public `is_sainted_item` predicate so it returns false and prevents the reference mod from applying a second classification. Unqualified items then continue through the existing function chain, preserving native behavior and unrelated rarity integrations. If BetterInventory's custom tier or the whole mod is disabled, the compatibility wrapper delegates to Red Weapons At Home's original predicate immediately.

Wrapper ownership is stored on the shared module/mod tables so a DMF rehook or BetterInventory reload replaces the previous wrapper instead of nesting recursively.

## CPU and memory boundaries

- Settings and the two shared colour tables are rebuilt only on enable, reset, or a `custom_tier_` setting change.
- Classification is bounded to one Power read plus at most five weapon modifiers or one Curio primary trait.
- No update callback, widget scan, timer, coroutine, promise, or account request is added.
- No per-item cache or retained view/widget reference exists.
- Repeated matching returns the same shared colour tables and allocates no colour table per card.

## Regression contract

`tests/test_custom_tier.py` covers exact reference defaults, every supported item category, optional weapon filters, per-type Curio filters, malformed input, colour/name overrides, shared-colour reuse, Red Weapons At Home suppression and restoration, and idempotent installation. The branch matrix treats standalone classification plus simultaneous-mod ownership as release-critical.
