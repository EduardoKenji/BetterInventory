## Purpose

This is the execution source of truth after B20. It supersedes the original Luna B21-B34 proposal after an independent commit-by-commit review found release-blocking persistence and CI defects plus unresolved manual-discard, equip, overview-refresh, and report-queue gaps.

The roadmap is ordered by risk and dependency. Safety and test trustworthiness come before profiling and large extraction. A batch should normally be one to three focused commits and must not mix an unrelated performance change with a state-machine or architecture migration.

## Current position

- B0-B20 have been implemented and recorded; “complete” in the historical ledger means the stated batch was delivered, not that every adjacent risk is closed.
- Local automated verification passes, the installed runtime matches the branch, and tracked archive parity passes.
- Practical in-game validation is ongoing.
- BI-021 and BI-022 are newly confirmed defects in B12 and B16.
- BI-023, BI-025, BI-026, and BI-027 are newly recorded residual gaps.
- BI-024 is a medium-confidence native async/reconciliation issue requiring instrumentation before behavioral intervention.

## Batch execution contract

Every batch must include:

1. A scope statement naming findings and files.
2. A failing regression/contract test before production behavior changes, whenever deterministic reproduction is possible.
3. Separate test and implementation commits when either part is non-trivial.
4. Focused tests plus the full repository verifier.
5. `git diff --check` and tracked archive parity when packaged runtime files change.
6. An explicit in-game gate recorded as `pass`, `fail`, or `not run`.
7. Updates to the full audit ledger and this roadmap.

New regressions discovered during practical validation are inserted as the smallest hotfix batch before the next dependent batch. Do not hide them in an architecture extraction.

### B22 — Correct customization persistence contract

Findings: BI-021 and residual BI-012.
Dependency: none; first implementation batch.

Suggested commits:

- `test: model DMF no-return persistence contract`
- `fix: stop retrying delegated customization saves`

Work:

- Reproduce installed DMF's non-throwing `nil` return in tests.
- Treat that outcome as delegated/attempted and end BetterInventory's periodic obligation.
- Retry only unavailable or thrown invocation according to a bounded policy.
- Preserve forced lifecycle flush without claiming durable success the API cannot report.
- Remove static verifier assertions that require `save_result == true`.

Exit gate: one mutation causes one deferred call under normal DMF behavior; repeated updates do not call synchronous save forever; thrown/unavailable paths are bounded and observable.

In-game gate: rename/color/edit/delete customization, idle for at least ten seconds, leave/reopen inventory, restart game, verify persistence and no repeated BetterInventory save warnings.

### B25 — Diagnose and harden rapid equipment persistence

Finding: BI-024.
Dependency: B23; must not depend on B24 implementation details.

Suggested commits:

- `test: model delayed native equip reconciliation`
- `fix: observe equipment persistence outcomes across view generations`

Work:

- Observe the existing native equip promise; do not issue a second backend write.
- Track slot, requested gear ID, generation, elapsed time, and true/false/error outcome with bounded diagnostics.
- Separate Darktide's three-second waiting-state timeout from actual promise completion.
- Refresh a reopened Character Overview when authoritative profile data confirms a late success.
- On failure, clear optimistic state and present authoritative equipment consistently.
- Ignore stale completion from an older character/view generation.

Exit gate: tests cover delayed success before/after reopen, false result, thrown rejection, timeout without completion, character switch, and stale generation. No path duplicates the equip request.

In-game gate: repeatedly equip then rapidly back out twice and reopen under normal and degraded network conditions; record terminal diagnostics and final server-authoritative gear.
