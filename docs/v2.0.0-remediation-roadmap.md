Date: 2026-08-07  
Branch: `audit/v2.0.0`  
Source audit: [v2.0.0-full-project-audit.md](v2.0.0-full-project-audit.md)

## Purpose

This is the execution plan after B0-B20. It turns the remaining audit follow-ups into small, reviewable batches. Each batch should normally be one focused pull request or one to three related commits. Do not combine performance work, state-machine changes, and large file extraction in the same batch.

The audit ledger remains the historical record of completed work. This roadmap is the source of truth for future batches.

## Current position

- B0-B20 have been processed and recorded in the audit ledger.
- Automated verification, schema checks, AST checks, coverage reporting, packaging checks, and archive parity currently pass.
- In-game validation of B0-B20 is in progress. Any reproducible regression found during that validation becomes a hotfix batch before the roadmap continues.
- No closed finding should be reopened without a new reproducer, failing regression test, or measurable production evidence.

## Batch execution rules

Every batch must contain the following before it is marked complete:

1. A short scope statement naming the finding IDs and files affected.
2. A deterministic regression or contract test before the production change when behavior changes.
3. A focused commit for tests and a focused commit for implementation when both are non-trivial.
4. `tests/verify.ps1`, `git diff --check`, and archive parity validation.
5. An explicit in-game gate marked `pass`, `fail`, or `not run`.
6. An update to the audit ledger and this roadmap.

If a batch discovers a new defect, stop the batch at the smallest safe boundary, record the reproducer, and create a new finding or hotfix batch. Do not hide unrelated fixes inside the same commit.
