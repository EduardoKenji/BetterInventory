# v3.4.1 Melk search, memory, and GodRolls audit

Date: 2026-08-29

## Scope

This audit covers repeated opening and closing of Sire Melk's Limited Time Acquisitions and GlobalStore Multi-Operative Supply, repeated Equipment Text Search queries in all supported grids, the reported GodRolls CPU spike while typing, and the final v3.4.0 Melk focus implementation.

The review used the current BetterInventory runtime, Darktide's local source mirror, GlobalStore's installed runtime, and the installed GodRolls implementation. It distinguishes retained Lua references from the allocator's reusable high-water mark: Lua memory does not have to return immediately to its startup number after a large store has been displayed, but live view generations must stop accumulating.

## Findings and fixes

### Exact Melk teardown was missing

Darktide's `class()` copies superclass functions into each child class table when that class is constructed. `MarksVendorView` therefore owns copied lifecycle functions; hooks installed later on `ItemGridViewBase` do not intercept Melk's copies.

v3.4.0 already used this fact to fix Melk input focus by hooking the exact `MarksVendorView._handle_input`, but teardown still relied on the base view hook. v3.4.1 adds exact `MarksVendorView.on_exit` and `MarksVendorView.destroy` cleanup. One idempotent guard makes the normal exit/destroy pair perform one cleanup, releasing the search index, query ranks, two retained visible-layout buffers, source-order maps, dim-alpha ownership, UI focus, marker-grid state, and transient item caches.

The shared cleanup now calls the direct search fallback only if closing the view session did not already run its registered search cleanup. This removes a redundant second release attempt.

GlobalStore already unloads live portrait resources when its final Credits or Marks vendor view is destroyed. BetterInventory's v3.2.5 generation retirement additionally unloads outgoing portraits before destructive category changes lose their widget IDs. No second GlobalStore portrait registry or broad third-party hook was justified.

### GodRolls was multiplied by query-time sorting

GodRolls hooks `Items.display_name` and `Items.weapon_lore_family_name`. For a weapon name it constructs `WeaponStats`, clones comparing stats, calculates maximum expertise projections, allocates and sorts potential-stat arrays, then formats markup. Darktide's native item comparators use display names as tie-breakers, so re-running the selected comparator during every search reorder could invoke this full path O(n log n) times.

Equipment Text Search does not need to re-run that comparator. Darktide's canonical `_grid_layout` is already ordered by BetterInventory priorities followed by the selected ItemSorting or native comparator. v3.4.1 partitions that existing order by search relevance, using canonical source position as the stable tie-break. This preserves the exact prior hierarchy among equal-ranked items and avoids calling GodRolls or any other selected comparator while typing.

The retained reorder path now resolves each entry's search rank once, stores only bounded scalar ranks and source positions, and uses those maps inside `table.sort`. It continues to reuse the same card widgets and two visible-layout buffers; no presentation rebuild or card reallocation is introduced.

### Query and close allocation review

Rapid input remains coalesced behind the existing 80 ms settle delay. Same-value polling is a no-op, one projection context and one weak rank map are reused, and the cached item index stays bounded to the active view. Search reorders clear and refill retained scalar maps rather than allocating new maps per query.

On release, v3.4.1 no longer allocates a replacement weak rank table for a state that is immediately removed. It clears the state's owned references and stores an optional remembered query as one bounded string instead of a one-field table. Earlier table-shaped remembered values remain readable across hot reload.

## v3.4.0 focus cleanup review

The failed experimental paths are not present in the final branch:

- no parent `_handle_back_pressed` interception remains;
- no invalid physical `esc` key lookup remains;
- no duplicate Melk focus hook remains.

The retained paths are all required and separately scoped:

- one exact `MarksVendorView._handle_input` hook, because inherited vendor hooks do not reach copied child methods;
- the mapped Back action for normal/controller input;
- Stingray's physical `escape` key because focused vendor text can suppress mapped Back;
- the physical left mouse button because clicks on empty vendor space do not invoke a card callback;
- the shared grid-card callback for supported views where a card was clicked.

Removing any one of the Melk-specific physical fallbacks would restore one of the confirmed v3.4.0 failures. The audit therefore removed no working focus guard; it regression-locks the absence of the discarded approaches instead.

## Verification boundaries

Automated coverage includes repeated Melk-like open/query/release cycles, idempotent exact lifecycle hooks, retained double-buffer identity, bounded rank/source maps, zero selected-comparator calls during repeated search commits, hot-reload closure retirement, and the existing GlobalStore portrait-generation stress test.

This source-level and harness evidence addresses BetterInventory-owned references and the reproduced GodRolls call multiplier. A live soak remains the final check for engine allocator behavior and for future versions of either optional mod.
